# Implementation notes

Updated 2026-10-16 (redesign v3: purple brand, plain-first services, pan-India).

## Decisions and deviations

| Item                | What was built                                                                                                    | Why                                                                                                                        |
| ------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Validation          | Hand-written shared validator (`lib/enquiry/schema.ts`), unit-tested                                              | Same rules in browser and server without a client-side library.                                                            |
| Forms               | Server action with `useActionState`; 3-step project form + 3-field callback form                                  | Works without JavaScript; no public JSON endpoint. Phone **or** email is enough (Indian SMB buyers prefer phone/WhatsApp). |
| Styling             | Hand-written CSS with tokens; Tailwind removed                                                                    | Small CSS (~49 KB unminified), no build plugin, easy to read.                                                              |
| Fonts               | `next/font/google` (Plus Jakarta Sans UI, Inter for the logo wordmark), self-hosted at build                      | Modern geometric face chosen by the owner; Inter matches the confirmed logo.                                               |
| Brand assets        | Committed PNG/ICO/OG generated by `scripts/build-brand.mjs` (sharp + local Inter)                                 | Builds don't depend on the generator.                                                                                      |
| CSP                 | `'unsafe-inline'` for scripts; everything else strict                                                             | Nonces would force dynamic rendering; no third-party scripts.                                                              |
| Long-form content   | Typed blocks in `content/knowledge.ts`                                                                            | Enough for articles; MDX can be added later if needed.                                                                     |
| FAQ structured data | Not used; FAQs are plain `<details>`                                                                              | Google limits FAQ rich results; the text stays crawlable and quotable.                                                     |
| Organization schema | `areaServed: India`, `knowsAbout`, `sameAs` (LinkedIn, Instagram), Social ScaleX as `subOrganization`; no address | Owner confirmed pan-India delivery; no address confirmed.                                                                  |
| `llms.txt`          | Generated from visible content                                                                                    | Low-cost summary for AI assistants; lists only published pages.                                                            |
| Location pages      | `/india/<state>/` publish only with unique `local` content                                                        | Template-only pages are "scaled content" and hurt rankings.                                                                |
| WhatsApp            | `wa.me` links with page-specific pre-filled text                                                                  | Fewer steps for the visitor; tells the team which page they came from.                                                     |
| Tracking            | `contact_click` events via `@vercel/analytics` `track()`                                                          | Measures which pages create enquiries; cookie-free.                                                                        |

## Visibility model

- `lib/env.ts` decides the environment: `SITE_ENV`, then `VERCEL_ENV`, else development.
- `lib/visibility.ts` is the single gate for hubs, sub-pages, guides, industries, regions, glossary, articles and work. `resolveRef()` returns `null` for hidden targets, so links to unpublished pages never render.
- `scripts/check-launch.ts` is the launch gate.

## Brand system

- **Logo:** confirmed owner logo — violet code brackets with a slash (`#8B5CF6`) + "CodeMindset" in Inter. Geometry in `components/brand/Logo.tsx` and `scripts/build-brand.mjs`.
- **Colours:** purple 600 `#7C3AED` (buttons, links; 5.7:1 on white), purple 800 `#5B21B6` (bold blocks; white text 8.6:1), purple 25/50 tints, ink `#0B0B0F`, text `#1F1B2D`/`#44414D`, muted `#5A5470` (7.3:1), dark `#120D1F`, one accent amber `#FBBF24` (only on purple/dark or with dark text).
- **Type:** Plus Jakarta Sans 400–800; fluid sizes with `clamp()`.
- **Layout:** container 1280 px; breakpoints 560 / 720 (phone action bar) / 1024 (desktop nav) / 1180 (header "Call us" text). Grids use `auto-fit` with `gridStyle()` to avoid lonely last rows.

## Verification done in this environment (2026-10-16)

The npm registry is blocked here, so the real `next build`, ESLint, Vitest and Playwright runs happen in CI. Locally:

- Real `tsc --noEmit` (TypeScript with React 19 + Next 16 types) — 0 errors; ESLint (Next core-web-vitals + TypeScript rules) — 0 problems; Prettier applied.
- 48 unit tests (Vitest API shim on `node:test`) — pass.
- All 149 sitemap routes server-rendered with React 19 and hydrated in Chromium: no hydration or console errors, exactly one `h1` each, no horizontal overflow at 360, 768, 834, 1024 and 1440 px, phone number only in the footer.
- Interactions checked: mega-menu (click, hover, Escape + focus return), industries dropdown, mobile menu, chooser (click + arrow keys), 3-step form validation and pre-selection, callback validation, tap targets ≥ 44 px.
